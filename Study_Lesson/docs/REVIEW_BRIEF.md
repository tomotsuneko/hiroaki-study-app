# 全体見直しの作業要領（点検担当向け）

完成済みの学習内容マップ（`data/*.py` → `output/*.md`）を、次の2つの視点で点検し、過不足を直す。あわせて単元の「ねらい」と「前提単元」を記入する。作りと欄の意味は `README.md` と `data/common.py`、作成時の規則は `docs/WORKER_BRIEF.md`（中学は `docs/WORKER_BRIEF_JHS.md` も）を参照。

- **視点1：受験に特化した教育の専門家**として、入試で問われる内容が過不足なく、正確に、入試での扱いが分かる形で載っているか。
- **視点2：この後コマごとの学習コンテンツ（教材・問題）を生成する**前提で、各コマの要点が分かりやすく、前後の繋がりと区切りが適切か。

## 1. 担当範囲と編集してよいもの

- 編集してよいのは、依頼文で指定した `data/<モジュール>.py` だけ。`data/common.py`、`tools/` の共通ツール、他の担当のファイルは編集しない。
- 自分用のスクリプトは `tools/worker/` に置く（名前は `<モジュール>_review_*.py`）。
- 見直しの記録は `reports/review/<モジュール>.md` に書く（様式は 6.）。
- `tools/rebuild_all.py` と `tools/export_json.py` は全資料を書き出すため実行しない（最後に取りまとめ役が実行する）。自分の資料は `python tools/build_md.py data.<モジュール> "output/<出力名>.md"` で生成する。出力名は `tools/rebuild_all.py` の OUTPUTS を見る。
- Google ドライブ上のため、ファイル編集の直後に Python が古い内容を読むことがある。編集後は数秒待ってから実行し、結果が変わらないときは再実行する。

## 2. 変えてはいけないこと（従来の規則）

- 区分（学年・科目）の合計コマ数＝標準授業時数。単元のコマ数は教科書会社の配当時数の範囲内（build_md の検証5）。行を足すときは同じ単元の中で統合・削除して合計を保つ。
- 学習指導要領の全内容項目がどこかの行の根拠に含まれること（検証2）。
- 教科書レベルの語句（人名・年号・用語など）を新たに補うときは、教科書会社の公開資料で確認できたものに限り、出典を SOURCES に加え、要点の末尾に「［語句：S番号］」を付け、行に † を付ける。確認できない語は載せない。
  - 例外：制度・機関・法令に関する事実（選挙制度、国会・内閣・裁判所の仕組み、中央銀行の政策手段、国際機関の仕組み、社会保障制度など）は、法令の条文（e-Gov）や所管の公的機関（省庁・日本銀行・国際連合広報センターなど）の一次資料で確認できれば、その資料を出典として同じ書式で載せてよい。人名・学説・出来事などの語句は、従来どおり教科書会社の公開資料で確認する。
- † の行は削らない。教科書の「発展」扱いの内容、学習指導要領の範囲外の内容は載せない。
- 入試列の意味：○＝出題範囲、△＝出題範囲の内容だが活動そのもの（実演・発表・討論・レポート作成など）は筆記の学力検査で直接は問われにくい、—＝出題範囲外、空欄＝未指定（個別試験）。共通テストは令和9年度実施要項、千葉県は令和9年度の出題方針（`sources/text/chiba_r9_houshin.txt`）の原文に基づく。
- 行ID（`rid`）は変えない。行を削除したらその ID は欠番にし、再利用しない。新しい行は rid を書かずに追加し、`python tools/assign_ids.py data.<モジュール>` で振る。行の並べ替えでは rid を行と一緒に動かす。

## 3. 視点1の点検項目（受験の専門家）

1. **正確さ**：要点の事実・定義・法則・文法の説明に誤りがないか。法令・制度は現行のものか（必要なら e-Gov で確認）。数式・化学式・英文例の誤記。
2. **重要事項の欠落・薄さ**：学習指導要領・解説に明記され、入試で問われる基本事項（公式・定理・法則・重要な用語・文法事項・読解の技能など）が、行の名称か要点に現れているか。解説にあるのに見当たらない事項は、同じ単元の中でコマ数を保って加える（例示の多い行を統合する、演習の行の範囲を明示して含める等）。
3. **入試列の妥当性**：各行の ○・△・— が上記の意味と出典の原文に合っているか。共通テストの科目は、大学入試センターの「令和9年度大学入学共通テスト問題作成方針」（公表されていれば。見つけたら SOURCES に加える）とも照らし、注（EXAM_NOTE）の説明が正確か。千葉県は教科ごとの出題方針の原文と照らす。
4. **入試対策上の配置**：単元末の演習、学年・科目末の復習の範囲が入試の頻出分野を押さえているか（コマ数は変えずに範囲の書き方で調整する）。
5. **同じ教科の学年間・科目間**：同じ内容を2か所で新出扱いしていないか、学年の配当が注と食い違っていないか。

## 4. 視点2の点検項目（コマごとの教材生成）

1. **要点の書き方**（全行）
   - 1文目：そのコマの中心内容を具体的に書く（何を・どこまで）。文末は到達が分かる形（「〜を理解する」「〜を求めることができる」「〜を見いだす」「〜を説明する」など）。
   - 2文目以降（任意）：扱う例・場面・活動、注意点。例は解説にあるものを優先する。
   - 教科書の語句を補った行は、末尾を「主な語句：A、B、C。［語句：S12］」の形にそろえる（語句ごとに出典が違う場合は［A：S8、B：S11］のままでよい）。
   - 長さは出典の印と末尾の「主な語句：…」を除いた本文で 40〜180 字を目安にする。1つの概念を扱う行（数学・理科に多い）で内容が明確なら 25 字以上でよく、無理に伸ばさない。220 字を超える行は、解説の問いの引用などを削り、要点を先に書く。**字数の目安は内容の正確さ・網羅より優先しない**。入試や学習に必要な事項を削ってまで収める必要はない（残す理由を記録に書く）。
   - 「理解を深める」「考える」だけで終わり、何を身に付けるのか分からない行を直す。
2. **区切り**：1行＝授業1コマで扱える量か。関係の薄い内容を1行に詰めていないか。逆に同じ内容の行が重複していないか。
3. **前後の繋がり**：単元の中で、前提となる内容が先に来ているか（学習→活用→演習の順、復習は最後）。単元の順序が学習の系統に合っているか（教科書会社の配列を参考に、変える場合は注に理由を書く）。
4. **演習・練習・復習の行**：何を練習するのか、どの範囲を復習するのかを名前か要点で明示する。同じ資料の中で同名の行を作らない（範囲を名前に入れる）。
5. **根拠の空欄**：復習以外の行で根拠コードが空の行をなくす。

## 5. 単元の「ねらい」と「前提単元」の記入（全単元）

- `Unit(..., aim="…")`：単元のねらいを1〜2文で書く。学習指導要領の当該内容の柱書・事項と解説の趣旨に基づき、その単元で身に付ける知識・技能と思考力等を具体的に書く。宣伝的な表現や教科書固有の題材名は使わない。復習の単元は「〜の範囲を復習し…」と範囲を書く。
- `Unit(..., prereq=[…])`：その単元の学習に直接必要な前の単元（1〜3件程度）。
  - 同じ資料の単元は `"uid"`、別の資料の単元は `"<モジュール名>:<uid>"`（例 `"jhs_math:3-2"`）。参照できる単元は `output/json/units.jsonl` の `ref` で確かめる（存在しない参照は lint で ERROR になる）。
  - 根拠は、解説の系統の記述（「中学校第3学年の〜を踏まえ」「『物理基礎』の〜を基礎として」など）、学習指導要領の履修の順序の規定、同じ内容の学年・科目の配列。推測で広く付けず、直接の前提に絞る。
  - 資料の最初の単元で前提がこの資料群に無い場合（中学1年の最初の単元など）は空でよい。
  - 復習・課題学習だけの単元は prereq を空にし、扱う範囲は aim に書く（前提単元は「直接の前提」に限るため。2026-09-29 に全資料でそろえた）。
- aim と prereq は `Unit(...)` の引数の最後にキーワード引数で書く。

## 6. 完了条件と記録

1. `python tools/build_md.py data.<モジュール> "output/<出力名>.md"` の検証がすべて OK。
2. `python tools/lint.py` で自分の資料の ERROR が 0。WARN は直すか、残す理由を記録に書く。
3. 語句を補った資料（歴史総合・日本史探究・世界史探究・公共・倫理・中学社会）は、`python tools/checks/run_all.py` で自分の資料の照合が NG 0。
4. 変更した行の2割以上（少なくとも10行）を無作為に選び、解説本文（`sources/text/` の該当テキスト）と照合する。
5. `reports/review/<モジュール>.md` に次を書く：
   - 点検の要約（視点1・視点2それぞれ、見つけた問題の種類と件数）
   - 主な変更（行ID、変更前→変更後の要点。軽い言い回しの統一は件数だけでよい）
   - 追加・統合・削除した行と、そのコマ数の出し入れ
   - ねらい・前提単元の記入数
   - 利用者の判断が必要な点（あれば）
6. 最終報告（日本語、短く）：記録ファイルのパス、上の要約、検証結果、判断が必要な点。
