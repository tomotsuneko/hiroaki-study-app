# 学習コンテンツ制作ガイド（1コマ1ページの Web 教材）

学習内容マップ（`data/`・`output/`）の1行＝授業1コマ（50分）に対応する Web ページを、**正確に・漏れなく・分かりやすく**作るための、定義・流れ・仕様・書き方・教科別の規則・点検（クロスチェック）のすべてをまとめた指示書。**このファイルだけを読んだ AI が、同じ品質のページを作り、同じ基準で点検・改修できること**を目的にする。

- 地図のデータの意味と作り方：`docs/SPECIFICATION.md`
- 地図の判断基準（範囲・†・入試の印・根拠の優先順・判例集・利用者の決定）：`docs/AI_MAINTENANCE_GUIDE.md`（本書と食い違うときは、地図の判断はそちらを優先する）
- 雛形：`lessons/_template.html`／共通の見た目と動き：`lessons/assets/lesson.css`・`lesson.js`／点検：`tools/check_lesson.py`

## 0. 用語

| 用語 | 意味 |
|---|---|
| 地図 | 学習内容マップ。1行＝1コマ。行ID（rid、例 `数Ⅰ-041`）と全体ID（`<モジュール名>/<rid>`、例 `hs_math_1a/数Ⅰ-041`）を持つ |
| 要点 | 行の `summary`。出典の印と「主な語句」を除いた本文が `summary_core` |
| 主な語句 | 行の `key_terms`（要点末尾の「主な語句：…」）。ページに必ず出す語 |
| † | 解説に明記がない教科書レベルの内容・語句（A 内容／B 語句／C 制度）。扱いの深さに注意する |
| 入試の印 | `exam`。○＝出題範囲、△＝範囲内だが活動そのものは筆記で問われにくい、—＝範囲外、空欄＝未指定（個別試験） |
| はざまの内容 | このコマで使う前提のうち、**地図のどの行でも教わらない**もの。ページ内で補足し、記録する |
| 解説 | 学習指導要領解説（教科別）。扱いの程度（「理解する」「触れる」）と例示の根拠 |
| meta | 各ページに埋め込む JSON（`<script type="application/json" id="lesson-meta">`）。目標・節・問題の対応、語句、前提と出どころ、出典を持つ |
| 取りまとめ役 | 分担作成で、割り当て・統合・点検・地図の修正判断を行う者 |

## 1. 目的・読者・品質の定義

- **読者**：高校生（中学の資料では中学生）。自宅や授業で、スマートフォン・タブレット・PC のブラウザで読む。
- **1ページ＝1コマ**：読んで学ぶ部分 25〜30分、確認問題 15〜20分が目安。
- **品質の定義**（すべて満たす）
  1. **正確**：事実・数値・引用・文法・入試の扱いに誤りがなく、根拠を示せる（出典のない事実を書かない）。
  2. **漏れがない**：地図の要点のすべての部分、主な語句、解説が求める事項を扱い、前提（はざまの内容を含む）を確かめてから本題に入る。
  3. **分かりやすい**：初めて学ぶ生徒が、このページだけで理解できる。用語は初出で定義し、具体と抽象を往復し、図と例題で支える。
  4. **確かめられる**：目標ごとに確認問題があり、基本・標準・入試の3段階で、解説が誤答の理由まで書いている。
  5. **繋がりが分かる**：前後のコマ、前提単元、入試での扱いが分かる。
  6. **動く**：点検ツールで ERROR 0、数式・図・操作部品が崩れず、スマートフォン幅でも横にはみ出さない。

## 2. 全体の流れ

### 2.1 一人で1ページを作る場合

| 段階 | すること | 成果物 |
|---|---|---|
| 1 選定 | 作る行を決める（テスト生成では 2.3 の基準で「最も難しいコマ」） | 選んだ理由と比べた候補 |
| 2 入力の収集 | 3章の入力をすべて読む | メモ |
| 3 設計 | 4章：到達目標、前提の出どころ、はざまの内容、範囲の境界、目標↔節↔問題の対応 | meta の骨組み |
| 4 根拠の収集 | 事実・語句・数値・引用の出典を集める。引用本文は公開本文を取得して保存 | `sources/text/` の保存物、出典一覧 |
| 5 執筆 | 雛形をコピーし、5・6章に沿って本文・図・問題を書く | `lessons/<モジュール名>/<rid>.html` |
| 6 検証 | 12章：検算スクリプト、事実の照合、図の座標・重なり、操作部品の動作、点検ツール | `tools/worker/lesson_<モジュール名>_<rid>_verify.py` ほか |
| 7 自己点検 | 13.3 のチェックリストを自分で一通り | — |
| 8 クロスチェック | 作成者以外が13章の手順で点検・改修 | 点検記録 |
| 9 記録 | はざまの内容を `reports/lesson_map_gaps.md` に、目次を更新 | 記録、`lessons/index.html` |

### 2.2 分担して多数のページを作る場合（取りまとめ役の手順）

1. **割り当て**：科目（または単元）ごとに担当を分け、担当ごとに編集してよいフォルダを明示する。同じ行を2人が作らないよう、割り当て表を作る。
   - **1つの単元を複数の担当で分けるときは、最初に「単元の表記表」を配る**：用語（例：整式／多項式）、置き換えの文字（例：\(X\) にそろえる）、公式・性質の番号の付け方、位置づけの書き方（「この時間（数Ⅰ-006）」）、同じ前提の出どころ（例：長方形の面積＝中1-029）。担当の境目でこれらが食い違った実例がある。表は `docs/notation/<モジュール名>.md` に置き（例：`docs/notation/hs_math_1a.md`）、担当が見つけた決め事で更新して後の担当に渡す。
2. **起動**：並行作業のエージェントは**一度に2つまで**起動し、起動数を確かめてから次を起動する（一度に多数起動すると同じ依頼が重複して起動した実例がある）。起動を確かめても、同じ依頼の担当が並行して同じファイルを編集していた例がある（点検担当）。そのため担当には、編集の前に対象のページの控えを %TEMP% に取らせ、終わりに控えとの差分で意図しない変更がないかを確かめさせる。
3. **受け取り**（担当の完了ごと）：
   - `python tools/check_lesson.py <ページ>` を自分で実行する。
   - 報告の「確信の持てない点」を1つずつ判断する（根拠を探して補う／ページに注記する／地図の不足として記録する／利用者に確認する）。
   - 報告の「地図の不足」を `reports/lesson_map_gaps.md` に追記する（14.1）。
   - 担当が `tools/worker/` に保存した出典の本文をページが引いていたら、`sources/text/` に写して `sources/registry/` に記録し（URL・取得日・ハッシュ）、ページの参照を書きかえる（担当は sources/ を編集できないため。数Ａ-031・050〜052・059〜062 で行った）。
   - 担当が「自分が作っていないファイル」を報告したら、すべての担当の記録（agent-transcripts）でその名前を探し、担当の最後の控えと今のページのハッシュを比べて、ページが書きかえられていないかを確かめる（2026-10-02、数Ａ-059〜063 の作業ファイル1つがどの記録にもない作業者に作られ、1つが書きかえられたが、ページは控えと一致していた）。
   - 同じページを2人が作ってしまったら、両方を点検し、内容（図・問題・前提の補足）が広く、根拠の規則を守っている版を採る。採らない版は `tools/worker/` に参考として残す。
4. **全体の点検**：全ページの点検ツール、ブラウザでの表示確認（12.5）、目次の再生成。表示確認を多数のページでまとめて行うときは、`python -m http.server <port> --directory lessons` を起動して `node tools/worker/lesson_scan_headless.js <port> hs_math_1a/数Ａ-001.html …` を使う（ヘッドレス Chrome で1ページずつ開き、命令ごと・全体に上限時間がある）。Cursor のブラウザの背景のタブで `tools/lesson_browser_scan.js` を動かすと、タブが裏にある間タイマーが間引かれ、4分で2ページしか進まないことがある。並行して作った単元は、全ページがそろった時点で `python tools/worker/lesson_find_future_refs.py`（すでに学んだ番号の前のコマを「〜で学びます」と未来の言い方で指している箇所を探す）を実行する（数Ａ-018〜023 で7か所あった。作成の時点で前のコマがまだなかったため）。担当によって図の色の値がずれていないかも数える（数Ａ-010・011 の橙が違っていた）。`python tools/worker/lesson_find_example_eq_answer.py` で、確認問題の入力の注意書きの例が同じページの正解と同じ値になっていないかも探す（2026-10-02 に数学Ⅰ・Ａの約68ページ・150件が見つかった。点検担当が見つけて直したのは一部だけだった）。
5. **クロスチェック**：作成者と別の担当が13章の手順で点検・改修する。
6. **地図への反映**：不足の記録を `docs/MAPFIX_BRIEF.md` の手順で判断・反映し、ページの meta を同期する（14.2）。
7. **利用者への報告**：結論（何ページ、点検結果）→ 仕組み → 見つかった不足 → 判断が必要な点。

### 2.3 テスト生成での行の選び方

科目ごとに「最も作るのが難しいコマ」を1つ選ぶ。候補を3つ挙げて次の観点で比べ、理由と比べた候補を meta の `selection_reason` に書く。

- 抽象度が高く誤解が生じやすい／前提が多く単元・学年・科目をまたぐ／図・操作・音声がないと理解しにくい／正確さの要求が高い（数値・年代・条文・文法）／入試で差がつきやすい。
- 条件：区分が「学習」「活用」（理科の「実験」、地歴公民の「探究」も可）。復習・演習の行は選ばない。共通テストの範囲の科目では入試の印が ○ の行。

## 3. 入力（必ず読むもの）

1. **対象の行**（`output/json/all_rows.jsonl`）：`summary_core`、`key_terms`、`term_sources`、`basis`（根拠コード）、`kaisetsu_page`、`exam`、`dagger`、`unit_aim`、`unit_prereq`、`prev_id`、`next_id`。
2. **同じ単元の全行と前後3コマ**（`output/json/<モジュール名>.json`）、単元の `note`。
3. **前提単元**（`unit_prereq`）の aim と行（`units.jsonl`、`all_rows.jsonl`）。
4. **学習指導要領本文**の該当事項と内容の取扱い（`sources/text/hs_cos_honbun.txt`、中学は `jhs_cos_honbun.txt`）。
5. **解説の該当ページと前後**（`sources/text/` の各教科の解説テキスト。`=== PDF p.N ===` の区切りと印刷ページはずれるので、ページ末尾の数字で確かめる）。扱いの程度と例示を確かめる。
6. **† の行の出典テキスト**（`term_sources` の S 番号 → その資料の `SOURCES` → `sources/text/`）。
7. **入試資料**：共通テストは実施要項（`sources/text/dnc_r9_jisshiyoukou.txt`）と問題作成方針（資料の `SOURCES` の URL）。中学は `sources/text/chiba_r9_houshin.txt`。
8. **地図の判断**：`docs/AI_MAINTENANCE_GUIDE.md` の判例集（9節）と利用者の決定（付録 C）。

## 4. 漏れを防ぐ設計（必ず行う）

### 4.1 到達目標への分解

- `summary_core` を節（「〜し、〜する」）ごとに分け、到達目標 O1, O2, …（2〜5個）にする。**要点のどの部分も、いずれかの目標に入れる。** meta の `objectives[].from` に対応する要点の部分を引用する。
- 目標の文は到達が分かる形（「〜を説明できる」「〜を求めることができる」「〜を読み取ることができる」）。ページのチェックリストと meta の `text` を一字一句そろえる。
- 解説がその根拠コードについて求めていること（理解させる事項・活動・例示）を、目標と本文に反映する。解説の例示は優先して使う。

### 4.2 前提の出どころ確認（はざまの内容の発見）

1. このコマの説明と問題で使う既習事項（用語・公式・技能・知識・記号）を**すべて**書き出す。
2. それぞれを教える行を `all_rows.jsonl` で探す（同じ資料の前の行 → 前提単元 → 前の学年・中学の資料 → 他教科）。見つかれば meta の `prerequisites[].taught_in` に全体IDを書く。
3. **どの行でも教えていない前提**（はざまの内容）は：
   - 「前回までの確認」に `.box.supplement`（id は `supp-1` など）で最小限の説明を置き、meta に `"gap": true, "where": "supp-1"` と書く。
   - 報告に「地図の不足」として挙げる（14.1）。
   - 後の行でしか扱わないもの（履修順の問題）も同じく補足し、`taught_in` に後の行、`gap: true` とする。
4. 主な既習事項は「前回までの確認」で小問にして確かめる（学んだコマの rid を示す）。既習の記号・用語でも、初出の直前に一言確認する（例：余事象の記号 \(\overline{A}\)）。
5. **補足の文言は、地図の状態と一致させる**。地図に出どころができたら「どの行にもない」「これまで扱っていない」などの文言を直す（14.2）。
6. **前提の出どころ（`taught_in`）にこのコマ自身を書かない。** 地図の要点に入った内容は前提ではなく、このコマの学習内容なので、目標（`from`・`text`）と本編で扱い、`prerequisites` からは外す（点検ツールが WARN にする）。
7. 前提の出どころの行は、その行の**要点に確かめたい語があるか**で確かめる（単元名や行名だけで判断しない）。
8. 並行して履修する科目（英コミⅠと論理・表現Ⅰなど）の行を前提にするときは「学びました」と断定せず、ページ内で最小限説明する。

### 4.3 範囲の境界

- 前後のコマで扱う内容は深入りしない。「次の時間へ」で何を次で扱うかを書き、meta の `out_of_scope` に「内容（扱うコマの rid）」を書く。
- 学習指導要領の範囲外（どの教科書も「発展」「参考」「研究」「コラム」扱い、他科目の内容）は載せない。
- 一部の教科書が本文、他社が発展・参考で扱う内容を使うときは、本文で「教科書によっては『発展』（『参考』）として扱われます」と注記する（例：地学基礎の温度と放射の関係、物理基礎の変位の節での密度変化、生物基礎の A細胞）。
- 扱いの程度は解説に合わせる（「触れる」内容は紹介程度にし、確認問題で深く問わない）。

### 4.4 対応の確認

- どの目標にも、本文の節（`sec-…`）が1つ以上、確認問題が1つ以上ある（meta の `sections`・`checks`）。
- 地図の `key_terms` はすべて本文と「重要語句」に出し、meta の `key_terms` にも載せる（地図の表記どおり。例：地図が「管理通貨制」ならその表記を含める）。
- 確認問題は基本・標準・入試の3段階をそろえ、全目標を覆う。

## 5. ページの構成と分量

h2 の id は次の順（点検ツールが必須とする）：`goals` → `review` → `intro` → `sec-1`…`sec-n` → `terms` → `summary` → `quiz` → `exam` → `next` → フッター（`footer.lesson-footer`）。

| 部分 | 内容 | 分量の目安 |
|---|---|---|
| ヘッダー | パンくず（学校 › 科目 › 単元 › rid）、小項目名、バッジ（授業1コマ／区分／入試の印／†）、導入の問いかけ（lead） | 1〜2文 |
| ねらい（goals） | 到達目標のチェックリスト、学習の位置づけ（前→今→次）、前提単元 | 目標2〜5 |
| 前回までの確認（review） | 既習事項の小問（学んだコマを明示）、はざまの補足 | 小問2〜3 |
| 導入（intro） | 身近な場面・現象・問いで動機付け。答えは本編で | 1つ |
| 本編（sec-1…） | 目標ごとの説明、図、例題（段階表示）、ポイント、よくある間違い | 2〜5節。本文は全体で 4,000〜10,000字程度（表・問題を除く。内容が必要なら超えてよい） |
| 重要語句（terms） | 地図の key_terms と、このコマの重要語の簡潔な説明 | — |
| まとめ（summary） | 目標に対応する要点（O番号を付ける）。数学・理科は公式カード | 3〜6項目 |
| 確認問題（quiz） | 選択・入力・記述。基本→標準→入試。全問に解説 | 6〜10問 |
| 入試へのつながり（exam） | 入試の印と、入試資料の原文に基づく位置づけ | — |
| 次の時間へ（next） | 次のコマとの繋がり、この時間では扱わないこと | — |
| フッター | 根拠（地図の ID・学習指導要領・解説ページ）、出典（URL）、作成日・版、注意書き（架空の資料など） | — |

### 5.1 区分（kind）ごとの組み立て

見出しの順（goals → … → next）は共通。区分に応じて中身を変える。

| 区分 | ねらい | 前回までの確認 | 本編 | 確認問題 |
|---|---|---|---|---|
| 学習 | 要点の節ごとの到達目標 | 前提の小問・はざまの補足 | 定義・性質 → 例題 → よくある間違い | 基本・標準・入試 6〜10問 |
| 活用 | 既習事項を場面に当てはめる目標 | 使う既習事項の総確認 | 場面（日常・他教科）→ 数学化・モデル化 → 解決 → 振り返り | 場面の問題を中心に 6〜10問 |
| 演習 | 要点に書かれた**問題の型**ごとの目標 | 範囲の要点・公式の総整理（公式カード） | 型ごとに例題（段階表示）と着眼点、型を見分ける手掛かり | 型を混ぜた 8〜10問。誤答の解説を厚く。単元末演習や、範囲の型が多い演習で、生徒が解く問題のない型が残るときは 13〜14問程度まで増やしてよい（数Ⅰ-020 は13問、数Ⅰ-056・067 は14問、数Ⅰ-078 は15問）。網羅は要点の語の下位の型（例：最大・最小なら軸が定義域の内側・外側・文字を含む）まで問題があるかで確かめる。**数えるのは生徒が解く確認問題だけ**で、例題・公式カード・「前回までの確認」の小問だけで扱った型は数えない（数Ａ-017 で「交互に並ぶ」「組に区別がある組分け」が抜けていた）。単元末演習は、範囲の途中の演習（数Ａ-017 など）が扱った型まで覆う（数Ａ-034 で 013 の図形への活用が抜けていた）。「型と練習する問題」の表は、各行の問題が本当にその型を扱っているかを確かめ、ねらいに書いた求めるもの（長さ・比・角・面積）ごとにそれを求める確認問題があるかも照合する（数Ａ-064 で面積を求める問題がなかった）。点の位置で式の形が分かれる型（方べきの定理の内部・外部・接線など）は、形ごとに確認問題で確かめる |
| 復習 | 範囲（単元・科目）の要点の総整理 | 範囲の要点の一覧 | 単元をまたぐ整理（対比表・関係図）と、つまずきやすい点 | 範囲全体から 8〜10問 |
| 課題学習（数学） | 解決の過程の段階ごとの目標（仮定・判断・振り返りを含む） | 使う既習事項の総確認 | 解説の流れ（①課題の理解 ②結果の予想 ③解決の方向の構想 ④解決 ⑤振り返りと発展）で節を立て、見出しに段階の印を付ける。予想を書く「考えよう」、記述問題（解答例と採点の観点）、操作部品で生徒の活動を支える | 記述を含む 6〜10問。仮定の吟味・言えることと言えないことの区別を問う |
| 実験・探究・実習 | 目的・方法・考察の目標 | 使う既習事項・安全 | 目的 → 仮説 → 方法 → 結果（架空と明記）→ 考察 → 振り返り | 結果の読み取り・考察の問題 |

演習・復習の行でも、はざまの内容の確認（4.2）と範囲の境界（4.3）は同じように行う。演習の行では新しい内容を導入しない（必要なら既習の行を示して確認するだけにする）。

### 5.2 順に作るときの `selection_reason`

テスト生成（2.3）以外で単元・科目を順に作るときは、`selection_reason` に「<科目> 単元『<単元名>』の順次作成（作成日）」と書く（点検ツールは項目の有無だけを確かめる）。

## 6. 書き方の基準（トーン＆マナー）

### 6.1 文体

- 生徒向けの本文は**「です・ます」調**。操作・活動の指示は「〜しよう」「〜してみよう」も可。見出しは内容が分かる言葉（問いの形も可）。
- 1文は短く（目安60字以内）、1段落は4行程度まで、1段落1つの考え。
- 断定してよいのは根拠のある事実だけ。解釈・評価は「〜と考えられます」「〜という見方があります」。
- 生徒を見下す言い方（「簡単です」「当然」「言うまでもなく」）、あおる言い方、絵文字、過度な感嘆符を使わない。
- 性別・地域・家庭環境などで偏りのない例を使う。実在の人物・団体・自治体を架空の設定に使わない（架空の「みどり市」のように名前も架空にし、架空と明記する）。

### 6.2 用語と記号

- 専門用語は**初出で定義**し、`<strong>` で示す。定義する前に使わない。記号（\(P_A(B)\)、Φ など）も定義してから使う。後の単元で学ぶ記号（⊂ など）を「まとめ」や公式カードで初めて使わない。使うなら、同じ文の中か前で意味を説明し、学ぶ行（「数Ⅰ-021 で学ぶ」）を示す。
- 教科書会社で用語が違うときは併記する（例：獲得免疫／適応免疫、寄進地系荘園／領域型荘園）。
- 学習指導要領・解説にない言い方を主にしない。広く使われる言い方は併記する（例：「上に開く（下に凸）」）。
- ページ独自の用語（例：「急変部」）も初出で定義する。同じ文字・記号を別の意味で使わない（例：関数 \(h(x)\) と高さ \(h\)）。
- 性質の一覧の中の話として「〜のときだけ」と書くときは、「このうち」と範囲を書く（「負の数をかける・わるときだけ向きが変わる」は性質①〜④の中での話）。
- 「〜でない」ことの根拠に定理の逆を使わない（「三平方の定理の逆から直角三角形でない」は論理が逆。根拠は定理そのものの対偶）。
- 「条件の数で式が決まる」と書くときは、決まらない場合を一言添える（例：3点が一直線上にあると二次関数は決まらない）。「方程式の組」と「その解」を取り違えない。
- 決まり・性質は**成り立つ範囲を示して書く**。「〜のときだけ」「いつも」「必ず」と書く文は、式や定義で同値かを確かめ、反例を探す（例：「\(L_n<R_n\) は増加関数のときだけ」は誤り。条件は \(f(0)<f(1)\)。「1文に although と but を入れない」は「although の節と主節を but でつながない」）。

### 6.2.1 ページ内の参照

- 本文で節を指すときは、**見出しに表示される番号か見出し名**で書く。h2 の id（`sec-1`）の番号は表示番号と2ずれる（goals=0、review=1、intro=2、sec-1=3 …）。
- 「〜で使います」「〜で確かめます」と書いた参照先で、実際に使っている・答えていることを確かめる。導入の問いには、答えた場所が分かるように書く（答えの囲みを置くか「導入の問い①の答え」と明示）。
- ほかのページの見出しや文を「　」で引くときは、原文どおりに写す（数Ａ-045 が数Ⅰ-071 の見出しを言い回しを変えて引いていた）。
- 証明しないで使う事実（図形の点の位置、点の個数、条件の十分性など）は、述べる箇所ごとに「このページでは証明せず、図（操作部品）で確かめる」と断る。例題の推論の前提にするとき、まとめ・公式カードに書くとき、演習・復習・単元末演習の解説で前提にするときも同じ（数Ａ-037・041・044・046・064・069）。
- 2つのページが互いの説明に頼り合っていないか（A の説明を B に任せ、B の説明が A を根拠にする循環）を確かめる（数Ａ-044 の十分性を 054 に任せ、054 が「三角形がかけるから」と 044 を根拠にしていた。054 を円周上の点を動かす説明に直した）。ページが独自に加えた説明・確かめ方は、meta だけでなく本文にも「このページでの説明」と書く。
- 「AかBの方法を使う」のように場合の分け方を挙げて全部を覆うように読める書き方は、本当に全部の場合を覆うかを乱数の図などで確かめる（数Ａ-047 で、∠APB が鈍角のとき2つの方法のどちらも使えない点があった）。

### 6.3 表記

- 数字は半角算用数字、単位は SI（記号は立体、数値と単位の間は必要に応じて空ける）。数式・変数は KaTeX で書く。
- 不等号は日本の教科書と地図の表記に合わせて **≦・≧**（KaTeX では `\leqq`・`\geqq`）にそろえる。≤・≥（`\le`・`\ge`）は使わない（点検ツールが WARN にする）。
- 括弧は全角（　）、引用・語の強調は「　」、書名・作品名は『　』、英文は半角。
- 年は「1929年」、世紀は「19世紀」。元号を使うときは西暦を併記する。
- 架空のデータ・資料・人物には「学習用に作成した架空の〜」と、その場で明記する。

### 6.4 説明の組み立て

- **具体 → 一般化 → 別の例で確認**の往復。抽象的な説明だけで終わらせない。
- **問い → 予想 → 説明 → 確認**。導入の問いに本編で答える（答えた箇所が分かるように書く）。
- 図・表・年表・対比表で、文字だけの説明を避ける。
- **よくある間違い**は「誤解 → なぜ違うか → 正しい考え方」の順で書く（`.box.caution`）。
- 例題は段階表示（`.worked .step`）で、各段階に「何に着目するか」を書く。

### 6.5 囲みの使い分け

| クラス | 用途 |
|---|---|
| `.box.goal` | この時間でできるようになること（目標のチェックリスト） |
| `.box.review` | 前回までの確認（小問） |
| `.box.supplement` | はざまの内容の補足（id は `supp-n`） |
| `.box.think` | 考えよう（問いかけ・予想） |
| `.box.point` | ポイント（核心） |
| `.box.caution` | よくある間違い・注意 |
| `.box.example` ＋ `.worked` | 例題（段階表示） |
| `.box.experiment` | 観察・実験（目的・準備・操作・結果・考察・安全） |
| `.box.source` | 史料・資料・データ（出典または架空の明記） |
| `.box.terms` | 重要語句（`dl`） |
| `.box.summary` | まとめ |
| `.box.exam` | 入試へのつながり |
| `.box.bridge` | 次の時間へ |

## 7. 正確さの規則（ハルシネーション防止）

### 7.1 根拠の優先順（地図の規則と同じ）

1. 学習指導要領本文 → 2. 解説 → 3. 入試の公式資料（実施要項・問題作成方針、千葉県の出題方針）→ 4. 教科書会社の公開資料（編修趣意書、会員登録なしで公開された年間指導計画・シラバス案・評価規準・内容解説資料・教科書紙面・ダイジェスト版・単元別資料一覧）→ 5. 法令（e-Gov）と所管の公的機関の一次資料（制度・機関・法令・統計・単位の事実に限る）。国立公文書館などが所蔵の公文書とともに公開する解説は、その公文書の事実（閣議決定の日付・内容など）の根拠にしてよい（判例 P-42）。

使ってはいけないもの：学校・個人のサイト、会員制の資料、出典の分からない二次情報、**自分の記憶や一般常識**、入試問題の問題文・選択肢（誤りの選択肢を含む。教科書会社の入試問題集にある会社の解説文は、教科書の扱いを示す根拠として使ってよい）。

### 7.2 事実の種類ごとの規則

| 種類 | 規則 |
|---|---|
| 教科の基本的な定義・定理・法則・文法 | 学習指導要領の範囲内で正確に書く。計算で確かめられるものは確かめる |
| 小学校で学ぶ内容 | 地図は中学校から始まるので、前提の補足で「小学校で学ぶ」と書くときは、`sources/text/jhs_cos_honbun.txt`（中学校学習指導要領の冊子。小学校学習指導要領の全文を収録）で学年と事項を確かめ、出典に書く（例：算数 第5学年〔用語・記号〕「最大公約数」）。「小学校で学んだ」と断定するのは本文で確かめた範囲だけにし、確かめられない部分は「このページでの約束」として分ける |
| 数値・計算の答え | **すべて Python で計算して確かめる**（fractions・decimal・math・statistics）。検算スクリプトを保存する |
| 歴史・公民・地理の人名・年号・出来事・制度 | 解説と地図の出典（地図のいずれかの資料に登録された出典。他科目・他学校段階の出典も可、meta に書く）で確かめられるものだけ。**年号は出典で出来事と結び付いて書かれているものだけ**。確かめられない年は書かず、必要なら「教科書で確認しよう」とする |
| 法令・制度 | e-Gov の条文、国会・省庁・地方公共団体（公開の例規集を含む）の資料。現行の法令に合わせる |
| 統計データ | 公的機関の資料で確かめ、出典と年（取得日）を書く。確かめられなければ「学習用の架空のデータ」と明記 |
| 物理・化学の定数・原子量 | 教科書で一般に用いられる値を使い、ページ内で値を示す。資料で値が違うものは「資料によって値が少し異なる。問題では与えられた値を使う」と書く |
| 生物・地学の代表的な値 | 出典で確かめられなければ、教科書で一般に用いられる値を「およそ」を付けて示す |
| 単位の定義 | 計量単位令（e-Gov）などで確かめる（例：磁束＝ウェーバ） |
| 入試の形式・傾向・配点 | 出典にないことは断定しない。位置づけは実施要項・問題作成方針の原文の引用で書く |

### 7.3 引用する本文

- **引用する本文（古典の原文、近代の作品、史料、原典の訳文）は、記憶で書かない。** 公開本文（青空文庫、ウィキソース日本語版、国立国会図書館・国文学研究資料館など）を取得して `sources/text/` に保存し、一字ずつ照合してから載せる。引用ごとに出典（資料名・URL・該当箇所）を示す。確かめられない本文は載せない（別の箇所に差し替える）。
- 公開本文の系統が教科書と違うことがある（『枕草子』『伊勢物語』など）。ページは取得した本文に合わせ、「教科書の本文と語句が違うことがある」と注記する。記憶にある教科書の形に書き換えない。
- 近代以降の日本の文章は、著作権の保護期間が終わった作品（著者の没年が1967年以前）か、このページのために書いた文章に限る。
- 英文・評論文・実用文・資料は、このページのために書く（入試問題・教科書の本文を写さない）。

### 7.3.1 見落としやすい「事実」

次も事実の記述なので、根拠を確かめる（クロスチェックで実際に見つかった型）。

- **出来事・人物の性格づけ**（「大規模な」「不安が広がった」「課題として残った」）。出典の記述を超えるなら、見方として示すか削る。
- **出典の語のつなぎ合わせ**。出典にない出来事名（例：「再び金の輸出を禁止」）や合成した人名の表記を作らない。
- **官職名で記された人物に実名を補うこと**（例：「小一条太政大臣」に根拠なく「藤原忠平」を付けた）。表記が公開本文と教科書で違うときは注記する（安倍仲麿／阿倍仲麻呂）。
- **作品の初出・作者の生没年**。青空文庫では図書カードに書かれているので、図書カードも保存して出典に示す。
- **思想家の概念の定義**。出典が思想家と語の対応・要点しか示さないときは、定義を言い切らず「このページの言い換え」と明示し、「教科書でも確かめよう」と添える。事実の照合は、語があるかだけでなく、ページが書いた定義文も対象にする。フッターの「確かめた範囲で書いた」は実態と合わせる。
- **導入・「ポイント」の「なぜ大事か」の一言**（例：「脳はグルコースを主に使う」）。
- **調査方法・調査対象の要約**。「聞き取りによる回答」などと1語でまとめず、出典の回収結果の内訳（面接・訪問・WEB・郵送など）と平均のベース（だれの平均か）に合わせる。
- **架空の例の固有名詞**。架空の市町村・会社・人物として作った名前が実在と重なることがある（「みどり市」は群馬県に実在）。架空の地名は「X市」「Y県」のような記号にする。
- **語の由来と呼び名の紹介**（例：「線がたすきのように交わることからたすき掛けという」「教科書によっては昇べきの順と呼ぶ」「単項式と多項式をまとめて整式という」）。編修趣意書・評価規準・解説などで確かめられなければ書かない。教科書で呼び方が分かれるときは、ページの呼び方を「このページでは」と明示し、両方を出典つきで書く。
- **法令の定義から導いた具体例**。同じ条の他の項（例外・大臣の定め）も読む。
- **記録先が内容で分かれる取引**（例：政府の無償資金協力は、緊急援助は第二次所得収支、施設整備は資本移転等収支）。例を決まる形に特定し、所管機関の資料で確かめる。
- **入試資料の引用**。問題作成方針の文が教科別か全教科共通かを区別して引用する。
- **教科書で「発展」「参考」の扱い**と注記するときは、その根拠（シラバス案・編修趣意書の該当箇所）をページの出典に書く。
- 教科の基本として書いた内容でも公開資料で確かめられない部分は、「〜とされています（教科書でも確かめよう）」と断定を弱め、確かめられた部分を先に書く。

### 7.4 確信の持てないとき

1. 根拠を探す（`sources/text/` を検索 → 地図の他の資料の出典 → 7.1 の公的資料をウェブで探す）。
2. 見つからなければ、**書かない**か、**断定しない形**にする（「〜という見方がある」「教科書で確認しよう」）。
3. 教科書によって扱いが違うものは注記する（4.3）。
4. 報告の「確信の持てない点」に必ず書く（取りまとめ役が判断する）。

## 8. 図・操作部品・数式・音声

### 8.1 図（SVG）

- 図は SVG で自分で描く。外部画像は使わない。`role="img"` と、図の内容を文章で表す `aria-label` を付け、`figure` と `figcaption`（図番号と説明）で囲む。
- **座標は計算で求める**（関数のグラフ、比率、角度、年表の目盛り）。座標を生成するスクリプトを保存する。
- 文字の重なり・はみ出しを点検する（文字幅の概算で、ラベルどうし、ラベルと線、図の枠）。
- 色だけに頼らない（線種・記号・文字でも区別する）。ダークモードでも読める色（`currentColor` を基本に、塗りは不透明度を下げる）。
- 模式図・単純化したモデルは、キャプションでそう明記する（例：「学習用に作成した模式図」「移動の幅を8度とした単純化したモデル」）。
- 経路・矢印の図（神経・ホルモン・イオンの向き・力の向き）は、線の始点と終点・線種・矢印の向きをスクリプトで確かめる。同じ名前の構造が別の役割で2回出るとき（静止時の K⁺チャネルと下降期の K⁺チャネル）は、別物であることを本文に書く。
- 年表の帯・括弧の端は、出典で確かめた年にだけ置く（確かめていない始まりの年に縦線を置くと「その年に始まった」と読める）。
- 横に並べた図を本文で「左の図・右の図」と指さない（390px では縦に並ぶ）。図の中の見出しや (i)(ii) で指す。
- 横に長い図（年表など）は `<div class="fig-scroll">` で囲む。スマートフォン幅で文字が読めないほど縮めず、横スクロールにする。390px の幅で文字が読めるかを確かめる。
- **生成スクリプトでページに書き込んだ部分を手で直したら、生成スクリプトも同じく直すか、書き込み処理を止める**（再実行で改修が消える）。

### 8.2 操作できる部品（ページ内スクリプト）

- 理解の助けになる場面で使う：スライダーで変化を見る図（関数・物理量・滴定）、段階実行（アルゴリズム）、切り替えで印を付ける本文（論証の部品）、思考実験。
- スクリプトはページ内に書き、外部ライブラリを使わない。表示する値は検算スクリプトと同じ式で計算し、**Node.js などで実行して、表示値が検算と一致することを確かめる**。
- 初期表示でも意味が分かるようにする（スクリプトが動かなくても本文だけで学べる）。
- **選択肢の全組合せ（または全刻み）を実行**し、規則表（活用表・接続、物理法則など）から求めた答えと照合する（例：文法の識別ナビがナ変で「死ぬ」＋体言を正解にしていた）。境目の値（衝・内合、中和点など）で意味のない表示にならないかも確かめる。
- 全刻みで、動く点・ラベルが図の範囲の中に入ることも確かめる（上に凸のグラフでスライダーの端にすると隣の点が図の外に出た例がある）。点が図の外に出る組合せを残すときは、点を描かないだけでなく文でも「図の範囲の外にある点は表示していない」と示す（図の点は1つなのに文は「共有点は2個」と食い違った例がある）。点の名前などの文字は、点や線と重ならない位置を探して置き、重なった文字をずらすときは元の左右・上下の順を保つ（数Ａ-063 で左右が入れかわっていた）（固定の向きに置くと、点が頂点に近い状態で重なった：数Ａ-041 で 550 状態中 93）。円を描く部品は、全状態で円が図の枠に収まるかも確かめる（数Ａ-044 で 1000 状態中 94 が切れていた）。静止した図でも、文字どうしの重なりだけでなく、文字と線（グラフの直線・点線）の交差も調べる（数Ａ-068 の図で、直線が4つの文字の上を通っていた）。getBBox による判定は字の上下の余白まで含むので、判定で出たものは3倍程度に拡大して撮影し、字形に線がかかっているかを目で確かめる。
- 全刻みの実行は、ページのスクリプトを Node.js の `vm` で偽の DOM（`getElementById` が value・textContent・innerHTML・addEventListener を持つ物を返す）の上で動かすと、ページを変えずに表示を書き出せる。表示の文字列を式として読み、独立の計算と照合する（例：`tools/worker/lesson_review_kazutoshiki_1_widgets.js`）。
- 表示の丸めは `toFixed` の誤差を避ける関数を使い、データは表示より2桁以上細かく持つ。a×10ⁿ の表記を自動で作るときは、仮数が10以上になったら桁を上げる（「10.0×10⁻⁶」を出さない）。

### 8.3 数式

- 文中 `\( … \)`、別行 `$$ … $$`、化学式 `\( \ce{…} \)`（KaTeX＋mhchem）。
- **HTML の中で数式に `<` を書くときは `&lt;` と書く**か、前後に空白を入れる（`a<b` はタグと解釈されて表示が崩れる。点検ツールが ERROR にする）。
- 長い別行数式は `.katex-display`（横スクロール）で収まる。文中の長い式（化学反応式など）は `<span class="eq-inline">\( … \)</span>` で囲む（スマートフォン幅ではみ出さない）。
- 波かっこの重なり（`P_{\overline{A}}` など）は書いてよい（点検ツールは数式を除いて雛形の書き残しを探す）。

### 8.4 音声（英語）

- 英文に読み上げボタン（`button.speak`、`data-lang="en-US"` 既定、速度は `#speak-rate`）を付ける。ブラウザの音声合成に依存するため、弱い音や強勢の再現は保証できないとフッターに注記する。

## 9. 確認問題の作り方

- 6〜10問。**基本→標準→入試**の順（`.quiz-level.lv1/lv2/lv3`）。各問に対応する目標（`.q-obj`）を書く。
- 形式：選択（`data-type="choice"`、正解の `button` に `data-correct="true"`、**正解はちょうど1つ**）、入力（`data-type="input"`、`data-accept` に正解の表記を `|` 区切りで。全角半角は正規化される）、記述（`data-type="open"`、`.model` に解答例と採点の観点、`.self-check` で自己評価）。
- **解説（`.explain`）は、正解の理由と、各誤答がどこで間違えたか**を書く。誤答は「よくある間違い」に基づいて作る（ありえない選択肢で数を合わせない）。
- 入試レベルの問題：資料・グラフの読み取り、複数の目標の組合せ、会話文・日常の場面の題材（共通テストの範囲の科目は1問以上。入試の形式だと断定しない）。個別試験を意識した記述は字数を指定し、解答例の字数を検算する。
- 問題文・選択肢・解説・本文の数値が互いに一致していることを確かめる（検算スクリプトで照合）。
- **正解の位置を散らす**（`lesson.js` は選択肢を並べ替えない。点検ツールは、選択4問以上で同じ位置が7割以上なら WARN）。並べ替えるときは `tools/worker/lesson_rebalance_choices.py`（2つの選択肢を入れ替え、解説の「Nつ目」も入れ替える）。
- 解説では選択肢を**位置（「2番目は」）でなく内容で参照する**のが望ましい。
- 演習・単元末演習の問題に、例題と同じ図形・同じ数値の問題を置かない（答えまで同じになった例がある）。この規則は学習の行の確認問題にも当てはめ、**本文の例・よくある間違いの囲みで解いてみせた問題、ほかの確認問題（解説に解き方が出ているもの）と同じ問題**も置かない（数Ａ-005・007〜010・012 で7問を差し替えた）。表裏・大小を入れかえただけのもの、題材だけを替えたもの（玉を人に、人を本に）、同じ設定で余事象を問うだけのもの、図形では頂点の名前を入れかえたもの・比を回しただけのもの・相似な配置や外部の点の配置でも計算が同じになるもの、空間図形では対称移動（立方体の回転・裏返し）で例題の組に移るもの・例題を縮尺しただけのものも同じ問題とみなす（数の組や名前の組の機械的な照合では拾えないので、対称移動で移るかを確かめ、通読でも確かめる。数Ａ-059・062・063 で9問を差し替えた）。差し替えるときは、差し替え先の数値も範囲のページで使われていないかを確かめる（数Ａ-025・026・034 で6問を差し替えた）。
- 誤答で取り違え（底と指数、分子と分母など）を区別するときは、取り違えても値が同じになる数を避ける（\(2^4=4^2\) の例）。
- 注意書きで「単位を付けてもよい」とした入力問題は、値を求めるすべての問題の `data-accept` に単位付きの形を入れる（数Ａ-006・007・011・012 で受付漏れがあった）。
- 入力の書き方の例（「2:1」「2<x<6」など）は、そのページの入力問題の正解とも誤答の値とも違う値にする（表記表の例をそのまま使い、6ページで例が正解と同じ、1ページで誤答と同じになっていた）。
- 誤答の解説に書いた式から、その誤答の値が本当に出るかを検算する（値が解説にあるかを見るだけでは見逃す。数Ａ-052 問4 は書いた式から別の値が出ていた）。範囲のページから誤答の説明を写すときも同じ（数Ａ-046 問3 の「半分にし忘れ」の説明を 064 が写していて、どちらも筋道から別の値が出た）。確認問題の数値・名前は、同じページのよくある間違いの囲みの中の例とも照合する。同じページの中で、ある問の数値が別の問の答えを明かさないようにする（数Ａ-053 問4・問5）。生成スクリプトで図を直したときは、書き込みの指定（`--write` など）で実際にページへ書き込んだことと、ページとの差分を確かめる。
- **誤答はよくある間違いから式で作り**、その作り方を検算スクリプトで再現する。再現できない誤答は数合わせとみなす。解説にはその値になる筋道を書く（「71日の半分」では筋道にならない）。同じ値の選択肢（約分の前後など）を置かない。
- 誤答の解説では、文法上成り立たないのか、文脈に合わないだけなのかを区別する（英語）。
- 選択問題の解説に、**すべての誤答の理由**があるかを機械的に照合する。
- 入力問題の `data-accept` は、ページで教えた別の語でも文が成り立つかで決める（例：while と whereas）。
- 不等号・マイナスの字形は `lesson.js` が照合の前にそろえる（≤・<=・≦ → ≦、≥・>=・≧ → ≧、−（U+2212）→ -）。`data-accept` には ≦・≧ の形だけ書けばよい。入力問題を作ったら、字形を変えた正解（≤、<=、全角の ＜＝）と、境界を誤った誤答（<）で照合を試す（`tools/worker/lesson_accept_norm_test.js` が例）。
- 空所補充の問題文に、正解を含む英文の読み上げボタンを置かない（答えが聞こえる）。
- 数表で「近い方をとる」問題・説明は、**ページに載せた桁数の値で差を計算**して確かめる。同じ距離なら表だけでは決まらないと明記する（正規分布表の 2.57 と 2.58 の例）。
- 記述問題の字数は空白を除いて数え、指定の ±10％以内にする（「120字程度」なら108〜132字）。
- 採点は `#quiz` の節の問題だけが対象（「前回までの確認」の小問は含まれない）。

## 10. 教科・科目別の規則と注意点

### 10.1 数学

- 流れ：定義・性質の意味を図で示す → 例題（段階表示）→ よくある間違い（場合分け・条件の落とし・等号）→ 練習。
- 答えは Fraction で厳密に計算し、場合分けは多数の値で総当たりと照合する。確率は全事象の数え上げでも確かめる。
- 確率：積事象・和事象の確率を問う問題では、誤った解き方（確率のかけ算・足し算）が偶然正解と一致する数値を使わない。とくに独立な試行を学ぶ前のページで、\(P(A)P(B)=P(A\cap B)\) となる数値を避ける。確率の積を、独立であることを確かめずに「同時に起こる確率」と説明しない（数Ａ-021・022・023 で直した）。期待値の和・差の性質（数学Ｂ）を、数学Ａのページで正しい方法のように読める説明をしない（数Ａ-030 で直した）。
- 関数・図形はスライダーで動かせる図が有効（表示値を検算と照合）。
- 共通テストの範囲の科目（数学Ⅰ・A・Ⅱ・B・C）は、日常の事象や会話文を題材にした問題を1問入れる。数学Ⅲは範囲外（印は—）。
- 教科書で「研究」「発展」の内容（例：原因の確率、数学C の3点の位置関係の一部）は、範囲外なら載せず、扱う場合は「教科書によって扱いの程度が異なる」と書く。
- 前提の履修順に注意（例：数学Ⅱの定積分で使う「はさみうち」は数学Ⅲで学ぶ → 数学Ⅱでは直観的に扱う。数学Bの Σ は数学Ⅲの前提）。
- 近い2つの数の差をとる計算は途中の値を5〜6けた残し、途中の値は四捨五入で書き写す（早い丸めで木星の公転周期が 4333 日になった例。正しくは約 4334 日）。
- 分布の形を仮定した数値（「約95％が入る範囲」）には、その場で仮定（正規分布とみなす）を書く。
- 日常の場面の命題・条件の問題では、考える範囲（全体集合）を問題文に書く（「体育の授業がある日だけを考えます」。書かないと読み方で真偽が変わった例がある）。
- 文字を含む範囲を答える問題では、誤答ごとに「何と取り違えたか」を書き分け、その取り違えの式で誤答の値が出ることを確かめる。
- 単元ごとの表記・用語・前提の出どころは `docs/notation/<モジュール名>.md`（2.2）に従う。

### 10.2 情報

- 共通テスト用プログラム表記（大学入試センター公表）に沿った疑似コード。「÷」は整数の商、「％」は余り、配列の添字は説明がなければ0から。表記を使う前に、使う表記だけ説明する。
- 動きの追跡表と段階実行の部品。比較・交換の回数など効率の計算は Python で確かめる。
- 入れ子の繰返しなど、構造の既習（情Ⅰ-037）を確認してから使う。
- 疑似コードで使う記号・書き方をコードから抜き出し、ページの表記の一覧にすべてあるかを照合する（`<=`、「,」で複数の文を1行に書く書き方などの抜けがあった）。

### 10.3 物理

- 流れ：現象 → モデル・法則（式と単位）→ 計算例 → 実験（目的・方法・対照・結果の読み取り・安全）→ 誤解の訂正。
- 向き（力・電流・磁界・誘導電流）は立体図と手順（「①変化を見る ②妨げる向き ③右ねじ」のような段階）で示す。
- 単位は SI。単位の定義は計量単位令（e-Gov）で確かめられる。
- 教科書で〈参考〉の内容（例：変位の節での密度・圧力の変化）は注記する。開口端補正のように数値の根拠がないものは定性的に書く。

### 10.4 化学

- 化学式・反応式は mhchem。文中の長い反応式は `.eq-inline`。
- 定数（電離定数・変色域など）は教科書で一般的な値を使い、「資料によって値が少し異なる。問題では与えられた値を使う」と書く。25℃など条件を書く。
- 滴定曲線などのグラフは計算で描く（混合後の体積の扱いを明記）。
- 実験の安全（保護眼鏡、試薬の性質、器具の扱い）を書く。結果の表が計算値なら「計算で作った学習用の値」と明記。
- 指示薬の例：メチルオレンジ・フェノールフタレイン（出典は地図の化学の資料を参照）。定数の注記（資料による値の違い）は図・表のキャプションにも書く。
- 丸めた境目の値を本文に書くときは、同じページの表・図の値と突き合わせ、「〜手前までに」「〜以内に」と書く（「9.99 mL で黄色」→厳密には 9.992 mL）。

### 10.5 生物

- 経路（神経・ホルモン・物質の流れ）は向きと名称を正確に図にする。
- 値（血糖濃度・静止電位など）は「およそ」を付ける。
- 教科書で「参考」の図にしか出ない語（例：A細胞）は、使うなら「教科書によっては『参考』の図などで扱われます」と注記する。
- 用語の社による違いを併記（獲得免疫／適応免疫）。範囲外と明言された内容（生物基礎の腎臓による体液濃度の調節の詳細など）は載せない。
- 実験・資料は架空のデータと明記し、既知の傾向に合わせる。

### 10.6 地学

- データは気象庁・国立天文台・NASA などの公的資料（取得日を書く）。太陽定数は気象庁が用いる値（1367 W/m²）を丸めて使い、資料による違いを注記する。
- 模式図（スペクトル、季節移動のモデル）は単純化したことを明記。天体の日付は国立天文台の暦で照合する。
- 他科目の前提（電磁波の区分、角速度）は、地学基礎で必ず学ぶ行があるかを確かめ、なければ補足する。

### 10.7 国語

- 目標は学習指導要領の事項（読む技能・書く技能）。教材名に依存しない。
- 教材文は 7.3 の条件を満たすもの。本文に行番号（`ol.lines`）を付け、設問で根拠の行を示す。
- **古典**：原文（公開本文と照合済み）・現代語訳（自作）・文法の注（品詞分解の表）・句法を並べる。系統差を注記。敬語は主体と対象の判定手順を示す（地の文と会話文の区別を前提として確認）。識別問題は「接続・意味・文脈」の手掛かりを明示する。撥音便の無表記（あなり・なめり）のような表記上の注意を書く。
- **近代の作品**：青空文庫などの本文と照合し、底本を示す。
- **評論・実用文**：自作し、架空と明記する。実用文（条例・広報など）の書式は公的な書き方に合わせ、根拠を示す（例：条例の号は「(1)(2)」、国の法律の号は漢数字＝参議院法制局・自治体の例規集。条例の定義＝日本国憲法第94条）。
- 記述問題は解答例と採点の観点（字数を検算）。
- 語り手・視点：作者と語り手の区別、三人称でも人物の視点と重なる語りがあることを解説に沿って書く。
- 引用の照合は、冒頭・末尾の断片でなく**全文**を照合する。引用本文の保存先は `sources/text/`（`tools/worker/` に置かない）。
- 導入文・例・操作部品の解説の手掛かりが、本文の規則やほかの判定と矛盾しないか確かめる（例：「文末で言い切るなら打消は『ず』」と教えながら「花咲かぬ」を言い切りの例にした）。

### 10.8 地理

- 統計は公的資料か架空と明記。人口密度などの計算は検算する。
- 図法は、解説が求める扱い（図法の名称と性格を結び付けて覚えさせない）に合わせ、「角度が正しい地図」「面積が正しい地図」のように性質で呼ぶ。正距方位図法など出典で確かめた名称は使ってよい。
- 地図・分布図は模式図として描き、方位・距離・最短経路などは計算で確かめる。
- 他科目の内容（地球の自転による風向の曲がり）は、地理の行では扱わない（利用者の決定）。必要ならページ内で補足する。

### 10.9 歴史（歴史総合・日本史探究・世界史探究）

- 流れ：問い → 背景 → 展開 → 結果・影響（因果）→ 比較・推移 → 資料の読み取り。年表・因果図・対比表を使う。
- 人名・年号・出来事・制度は、地図の出典で確かめたものだけ（7.2）。確かめられない年は書かない。
- 史料は公開本文と照合したものだけ。使えなければ「学習用に作成した架空の資料」と明記した資料問題にする。
- 教科書で用語が違うものは併記（寄進地系荘園／免田型・領域型荘園）。
- 評価の分かれる事柄は断定しない（複数の見方として示す）。思想家・人物と概念の対応は出典の文脈どおり。
- 7.3.1 の「性格づけ」「語のつなぎ合わせ」に特に注意する（歴史の文章で起きやすい）。年号を後から書き入れたら、本文・表・問題・年表の図（と図の生成スクリプト）をまとめて直す。
- 解説の「問い」を引くときは、どの単位（中項目・小項目・事象）の問いかを解説どおりに書く。

### 10.10 公民（公共・倫理・政治・経済）

- 制度は現行法令（e-Gov）と所管機関の資料（日本銀行・財務省・厚生労働省など）で確かめる。統計は取得日を書き、改訂の可能性を注記する。
- 思想家と概念の対応は出典どおり（判例 P-30）。原典は引用せず、要旨を自分の言葉で書く（引用するなら 7.3）。
- 架空の事例・話し合いの記録で考えさせる。価値判断を押し付けない（複数の立場の根拠を示す）。
- 経済のグラフ（需要・供給など）は計算で描き、数値は架空と明記する。
- 解説が語を示すだけの概念（「社会的余剰」など）は、モデルでの説明を「〜と考えることができる」の形にする。
- 統計の数値は取得し直して内訳の合計・恒等式を検算する（財務省の統計は見出しの列順から読む）。

### 10.11 英語（英コミⅠ〜Ⅲ・論理・表現Ⅰ〜Ⅲ）

- 目標の言語材料（文法・表現）と技能を明確に。英文はオリジナル（英コミⅠは CEFR A2〜B1、Ⅱは B1、Ⅲは B1〜B2 程度）。
- 文法は日本語で説明し、例文は英日対訳。読み上げボタンを付ける。
- **和訳・和文英訳の置き換え練習そのものは作らない**（学習指導要領が単なる置き換えの指導を制限）。日本語での要約・説明は可（判断が分かれうるので、要約・説明であることを明示する）。
- 話すこと・書くことは、手順・モデル・ルーブリック・解答例。語数・字数は検算する。
- 英米差・くだけた言い方の違いは注記する（例：提案の that 節の原形）。
- 地図の配当（P-25：分詞構文は英コミⅠで学習、Ⅱで活用 など）と、利用者の決定（部分否定・倒置・強調は英コミⅡで † 付き）に合わせて、前提の出どころを示す。
- 対比の例文・解答例が、説明している決まり・性質を本当に満たしているかを確かめる（「言い切る」例のつもりの This does not mean … は反対の主張ではなかった）。
- 要約・報告の伝達動詞は資料どうしで公平に選ぶ（ある資料だけ claims にしない）。
- 読み上げの注記（音声合成に依存）と、† の行ならヘッダーの † バッジを入れ忘れない。

### 11.3 meta（`lesson-meta`）

必須の項目：`id`、`map`、`rid`、`title`、`subject`、`unit{ref,title}`、`exam`、`basis`、`objectives`、`key_terms`、`prerequisites`、`out_of_scope`、`selection_reason`、`sources`、`version`、`generated`（書式は付録 A）。

- `title`・`basis`・`exam` は地図と完全に一致させる（点検ツールが照合）。
- `subject` は科目名だけ（「数学Ⅱ」「日本史探究」。「数学（数学Ⅱ）」のような形にしない）。
- `objectives[]`：`id`、`text`（ページのチェックリストと同じ文）、`from`（要点の引用）、`sections`（節の id）、`checks`（問題の id）。
- `key_terms[]`：`term`、`where`（その語を説明する節の id）。
- `prerequisites[]`：`concept`、`taught_in`（全体IDの配列）、`gap`（どの行でも教えていない、または後の行でしか教えないなら true）、`where`（補足の id）。
- `sources[]`：`name`、`publisher`、`url`、`use`（何を確かめたか）。フッターの出典と一致させる。

### 11.4 点検ツールが確かめること（`tools/check_lesson.py`）

ERROR：meta の有無と必須項目／地図に ID がある／置き場所／title・basis・exam の一致／必須の h2 とフッター／確認問題6問以上（`#quiz` の節）／各問の解説・正解数・`data-accept`・解答例／目標のチェックボックス・節・問題の参照／地図の主な語句が本文にある／語句・前提・補足の参照先がある／前提に出どころか gap がある／雛形の書き残し（`{{…}}`、TODO など）／許可外の外部読み込み／数式の `<` の直後が文字／`$$`・`\(` `\)` の対応。
WARN：前後の rid がページにない／本文の文字数（3,000〜30,000 以外）／出典が空／節の数がねらいより少ない／目標の文が本文と一致しない／地図の主な語句が meta.key_terms にない／**選択問題の正解の位置の偏り**（4問以上で同じ位置が7割以上）／**前提の出どころがこのコマ自身**／**不等号 ≤・≥（`\le`・`\ge`）**（コードの表示 `<pre class="code">` の中は対象外。まとめて直すときは `tools/worker/lesson_unify_ineq.py --write`）。

雛形の書き残しは `{{…}}`（数式の中は除く）、TODO、〇〇、「ここに〜を書く」の形を検出する（本文の普通の「ここに」は検出しない）。

## 12. 検証（作成者が行う）

1. **点検ツール**：`python tools/check_lesson.py lessons/<モジュール名>/<rid>.html` で ERROR 0。WARN は理由を確かめる。
2. **検算**：`tools/worker/lesson_<モジュール名>_<rid>_verify.py` に、ページのすべての数値（答え・表・図の座標・スライダーの表示値・解答例の字数・語数）を計算し、ページの記述と照合する処理を書く。
   - **ページに書いた値（与えた値・表の桁数）から計算した答えが、ページの答えと一致するか**で確かめる。「ページにその数字があるか」だけの照合や、丸める前の値だけでの比較では誤りを見逃す（実例：表の4桁では同距離なのに「2.58 の方が近い」、途中の丸めで 4333 日）。
   - 照合した件数を出力し、**0件で OK にならない**ようにする（図の座標の書式を読み取れず空振りした例）。
   - ページ中の数式の等号・近似の連なり（\(a=b=c\fallingdotseq d\)）を抜き出して、各段を独立に計算する照合が有効（無理数と小数を「=」でつないだ誤りが見つかった）。
   - 検算スクリプトにわざと誤りを入れたページの写しを読ませ、誤りを検出できるかを試す（変異試験）。
   - 選択問題は、ページの選択肢の式を読み取って照合する（問題文を書き写して計算するだけでは、選択肢の書き間違いを見逃す）。
   - 表（三角比表など）をページから読み取って使うときは、読み取った行数が期待どおりか（1°〜89° なら 89 行）を確かめる（強調表示の行を読み落としやすい）。
   - 誤答の値も、その誤りの式から計算して再現する。誤答の照合は「その語・値がページにあるか」ではなく、筋道の式を再現して行う。期待値を検算スクリプトに直書きすると、ページの誤りを見逃すので、値はページから読んで独立に計算した値と比べる。例題の文中の答え（「答え 72通り」など）も読み取って独立の値と照合する（等号の連なりの照合だけでは、答えの文の書き換えを見逃すことを変異試験で確かめた）。照合するのは「答え」の語より後ろの値にする（同じ段の式に正しい値があると、答えの書き換えを見逃す）。問題の設定（人数・個数・確率など）も検算スクリプトに書き写さず、問題文から読み取る（書き写すと、問題文の数の書き換えを見逃す。点検者の変異試験で見つかった）。
3. **事実の照合**：事実の記述（定義・法則・年代・人名・制度・数値・性格づけ）を一覧にし、根拠の本文（`sources/text/`）に実在するかを機械的に照合する（`…_facts.py`）。照合できないものは書き直すか削る。
4. **引用の照合**：引用本文を保存した公開本文と**全文**を一字ずつ照合する（`…_quotecheck.py`）。
5. **表示の確認**：
   - ブラウザで開く（`python -m http.server 8000 --directory lessons` → `http://127.0.0.1:8000/…`）。ブラウザを使えない環境では、ヘッドレス Chrome/Edge で撮影するか、座標計算で重なり・はみ出しを確かめる。
   - 数式の表示エラー（`.katex-error`）が0、描画されない数式の区切りが残っていない、図が0サイズでない、**1200px と 390px の幅で横にはみ出さない**。全ページをまとめて確かめるときは、目次を開いたブラウザのコンソールで `tools/lesson_browser_scan.js` の中身を実行する（問題のあるページだけが `problems` に出る）。
   - 操作部品を動かして表示値を確かめる。
   - 横のはみ出しは文書全体の `scrollWidth` と `clientWidth` の比較で確かめる（表の中の数式などで、見えないはみ出しが起きる）。要素ごとに調べるときは、KaTeX の読み上げ用 MathML（`.katex-mathml`）と根号などの幅広の SVG（親で切られる）を除く（誤検出になる。複数の担当が同じ誤検出に当たった）。
   - 表示確認用のサーバーは担当ごとに別のポートで起動し、終わったら止める（同じポートでぶつかった例がある）。
   - ヘッドレス Chrome/Edge のプロファイル（`--user-data-dir`）は Google ドライブの外（`%TEMP%` など）に置く（ドライブ上に置いてプロセスが終了できなくなった例がある）。
6. **自己点検**：13.3 のチェックリスト。

## 13. クロスチェック（作成者以外が行う）

### 13.1 目的と進め方

作成者と別の担当（別のエージェント）が、**抜け漏れ・分かりやすさ・ハルシネーション**を重点に点検し、必要なら直接改修する。改修後は12章の検証をやり直す。

1. 入力を読む：地図の行・単元・前後3コマ・解説の該当ページ・出典（3章）。
2. **生徒として通読**する（初めて学ぶ高校生のつもりで、上から順に。分からない所・引っかかる所に印を付ける）。
3. 13.3 のチェックリストで一項目ずつ確かめる。
4. 指摘を重大度で分類する（13.2）。S1・S2 は直す。S3 は手間が小さければ直す。
5. 直したら、点検ツール・検算・照合をやり直す。生成スクリプトで図を書き込んだページは、直す前に生成スクリプトを再実行して差分がないこと（図が手で直されていないこと）を確かめてから、スクリプト側を直す。
6. 記録を書く（付録 B）。作成者の判断を覆すときは根拠を書く。

### 13.2 重大度

| 重大度 | 例 | 対応 |
|---|---|---|
| S1 重大 | 事実・数値・答えの誤り／根拠のない事実（記憶による年号・人名・引用）／範囲外の内容を無注記で扱う／正解が2つある・正解がない問題／著作権のある本文の転載／入試の形式の断定 | 必ず直す |
| S2 中 | 要点の一部が抜けている／定義前の用語・記号／説明の飛躍・順序の不自然さ／前提の確認不足（はざまの見落とし）／解説が誤答の理由を書いていない／図と本文の不一致／根拠が弱い記述（断定を弱める・注記する） | 直す |
| S3 軽 | 表記ゆれ・誤字・冗長な表現・見出しの分かりにくさ | 手間が小さければ直す |

### 13.3 チェックリスト

**A 抜け漏れ（網羅）**

- [ ] 導入の問いに本編で答えている（答えた場所が分かる）。
- [ ] 地図の要点に後から加わった文が、目標の `from` と本編に入っている。前提の出どころにこのコマ自身がない。

**B 正確さ（ハルシネーション）**
- [ ] 事実の記述を一つずつ根拠と照合した（出典の本文を開いて確かめる。ページの出典欄にあるだけでは不十分）。PDF から保存した本文は康熙部首の字形（⾒・⽤・⼤ など）を含むので、機械的に照合するときは NFKC で正規化してから比べる（正規化しないと実在する語句を「ない」と誤判定する）。

- [ ] 数値・答え・図の座標・スライダーの値を再計算した（検算スクリプトを実行し、ページと一致）。
- [ ] 引用本文を公開本文と照合した。
- [ ] 教科書で「発展」「参考」の内容に注記がある。範囲外の内容がない。
- [ ] 入試について出典にない断定がない。
- [ ] 架空のデータ・資料・人物・自治体に架空の明記がある。
- [ ] 定義・定理・法則・文法に誤りがない（教科の専門家の目で）。
- [ ] 「〜のときだけ」「いつも」「必ず」を含む文に反例がない。決まりの範囲が示されている。

- [ ] 用語・記号を定義してから使っている。
- [ ] 1文・1段落が長すぎない。説明に飛躍がない（途中の式・理由が省かれていない）。

- [ ] よくある間違いを扱い、その理由を説明している。
- [ ] 例題の各段階に「何に着目するか」がある。

### 付録 B：記録の書式

**作成の報告（担当→取りまとめ役）**：ファイルのパス／選んだコマと理由（比べた候補）／到達目標／はざまの内容（地図の不足）／使った出典／検証の結果（点検ツール、検算、照合、表示）／確信の持てない点。

**クロスチェックの記録**（`reports/lesson_review/<担当名>.md`）

```markdown
## <全体ID>「<小項目名>」（点検日）

- 通読の所感：<生徒の視点で分かりにくかった所など>
- 指摘と対応
  | 重大度 | 箇所 | 指摘 | 対応 | 根拠 |
  |---|---|---|---|---|
- 検証：点検ツール ERROR n / WARN n、検算 <結果>、事実の照合 <件数と結果>、引用の照合 <結果>
- 地図の不足（新たに見つかったもの）：<…>
- 残した課題（直せなかった点と理由）：<…>
```

### 付録 C：コマンド一覧

| 目的 | コマンド |
|---|---|
| 1ページの点検 | `python tools/check_lesson.py lessons/<モジュール名>/<rid>.html` |
| 全ページの点検と目次の作成 | `python tools/check_lesson.py --index` |
| 全ページの一覧（科目・問題数・補足数・字数） | `python tools/worker/lesson_summary.py` |
| gap の前提の一覧 | `python tools/worker/lesson_sync_dump.py` |
| 地図の再生成 | `python tools/rebuild_all.py` |
| 語句の照合（地図） | `python tools/checks/run_all.py` |

| 表示の一括点検 | 上の目次を開いたブラウザのコンソールで `tools/lesson_browser_scan.js` を実行 |

Windows・PowerShell では実行前に `[Console]::OutputEncoding=[Text.Encoding]::UTF8; $env:PYTHONIOENCODING="utf-8"`。
