# 高校科目の学習内容マップ 作業要領（担当者向け）

この文書は、科目ごとの作業担当が共通で従う手順です。担当ごとの固有事項（科目・ファイル名・資料URL）は依頼文に書かれています。

## 目的と最重要ルール

- 高校受験・大学受験を想定した「学習内容の全容」を、大項目（科目）・中項目（単元）・小項目（授業1コマ＝50分）で整理する。
- 正確さが最優先。公的資料（文部科学省の学習指導要領・解説、大学入試センター、文部科学省公開の教科書編修趣意書）を根拠にし、確認できないことは書かない。推測で数値や内容を補わない。
- 成果物・報告はすべて日本語。

## 作業場所とツール（Windows / PowerShell）

- 作業フォルダ: `g:\マイドライブ\10.Tool_Cursor\curriculum_map`
- PowerShell では最初に `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONIOENCODING="utf-8"` を実行する。
- 既存ファイルの変更禁止: `tools/*.py`、`data/common.py`、他の担当の `data/*.py`・`output/*.md`。新規ファイルは作ってよい（自分用の抽出スクリプトは `tools/<自分のモジュール名>_*.py`）。
- ツール:
  - `python tools/fetch_pdf.py <key> <url>` … PDF を `sources/raw/<key>.pdf`、テキストを `sources/text/<key>.txt`（`=== PDF p.N ===` 区切り）に保存
  - `python tools/links.py <url> <out.txt> [filter]` … ページ内リンク一覧（テキスト\tURL）
  - `python tools/fetch_list.py <links.txt> <prefix> [filter]` … リンク一覧の PDF を一括取得
  - `python tools/kaisetsu_headings.py <key> <page_offset> <out.tsv> hs` … 解説の小見出し（「…（ア （ｱ） ， ［内容の取扱い］ （3） ）」形式）を印刷ページ付きで抽出
  - `python tools/find_terms.py <key> <page_offset> <out.tsv> 語1 語2 …` … 語句が解説の何ページに出るか
  - `python tools/hensyu_tables.py "<glob>" <out.txt>` … 編修趣意書 PDF の配当時数表を抽出（`sources/raw/<glob>.pdf` が対象）
  - `python tools/build_md.py data.<module> "output/<name>.md"` … Markdown 生成と自動検証
- 印刷ページと PDF ページのずれ: 各 PDF ページの冒頭付近にある「数字だけの行」を集計し、最頻値の差を使う。

## 合意済みの方針

1. 各行＝授業1コマ。列は 学年・科目／区分／小項目名／要点（1〜2文）／学習指導要領の根拠コード／解説ページ／入試フラグ。
2. コマ数は標準単位数×35 に一致させる（演習・単元末・予備＝復習のコマも含めて年間計画のように作る）。学習指導要領が「内容の(1)から(3)までの中から適宜選択させる」などと定める科目では、共通テストの出題範囲を標準単位数に充て、それ以外は `Unit(extra=True)` の別枠単元にする。
3. 入試列は `EXAM_COLUMNS = ["共通テスト", "個別試験"]`、`EXAM_DEFAULT = {"共通テスト": "○", "個別試験": ""}`。個別試験は基準大学が未指定のため空欄のまま（build_md.py が既定の説明文を付ける）。共通テストの範囲外の単元は `exam={"共通テスト": "—"}`。出題範囲には含まれるが共通テストの出題形式上は直接問われにくい行（話す・書く活動の実演など）は `"△"` を使ってよく、使う場合は意味を `EXAM_NOTE` に明記する。
4. 区分（kind）: 学習／活用／演習／実験（理科の観察・実験）／探究（地歴公民・理科の探究活動）／課題学習／復習。build_md.py はこれ以外の区分の行の共通テスト列を「—」にする。

## データモジュールの書き方

- `from data.common import R, Segment, Unit`
- 必須の変数: `SUBJECT`（例 "理科（物理基礎・物理）"）, `SCHOOL = "高等学校"`, `KAISETSU_NAME`, `HEADINGS_TSV`（抽出結果 TSV。使えない場合は空ファイルを作って指定）, `SEGMENTS`, `COS_ITEMS`, `TERMS`, `EXAM_COLUMNS`, `EXAM_DEFAULT`, `BASIS_NOTE`, `EXAM_NOTE`, `HEADER_LINES`, `LIMITATIONS`, `PUBLISHER_NAMES`, `SOURCES`, `UNITS`。任意: `KAISETSU_EXTRA`, `SHARED_PAGES`, `PUBLISHER_NOTE`, `FETCHED`。
- `SEGMENTS`: `Segment(キー文字列, 表示名, コマ数, 行の学年・科目表示, No.接頭辞, (解説の内容の印刷ページ開始, 終了))`。
- 根拠コード: 学習指導要領本文の記号体系をそのまま使う。例 `"(1)ア(ア)"`、大項目がある科目は `"A(1)ア(ア)"`、さらに下位の記号（理科の㋐など）がある場合は `"(1)ア(ア)㋐"`。全角カタカナ・半角括弧。内容の取扱いは `"取扱い(n)"`（下位があれば `"取扱い(1)ア"` 等）。他の科目の項目は `"<区分キー>:<コード>"`。
- `COS_ITEMS[区分キー]`: 本文の内容の全項目（ア(ア)…、イ(ア)…、下位記号まで）＋内容を追加・限定・指定する内容の取扱い。一般的な配慮だけの取扱いは入れない。build_md.py が「全項目がいずれかの行の根拠に含まれるか」「存在しない記号を使っていないか」を検証する。
- `TERMS[区分キー]`: 本文に［用語・記号］等の語句リストがあれば全部。無ければ空。
- 解説ページ（`R.page`）: その行の根拠コードの記述がある解説の印刷ページ（"66" や "84-85"）。build_md.py は `HEADINGS_TSV` と `KAISETSU_EXTRA` から「コード→ページ」を作って照合する。解説の見出し形式が `kaisetsu_headings.py` で取れない場合は、自分で抽出スクリプトを書いて `KAISETSU_EXTRA = {(区分キー, コード): "a-b", ...}` を作る（抜き取りで本文を読んで正しさを確認し、コメントに見出し名を書く）。
- `publishers`（単元ごと）: 編修趣意書の表から実際に読み取れた章の配当時数だけを記録する（推測・捏造禁止）。1社1冊の代表（標準単位数の時数に最も近い合計の本）を選び、`SOURCES` に発行者・教科書番号・URL を明記。単元と章が1対1に対応しない場合は近い形で対応付けて `note` に説明し、対応付けられない社はその単元では省く。build_md.py は単元のコマ数が掲載社の最小〜最大の範囲内かを検証する。教科書会社の合計が標準時数より少ない場合、差分は「復習（予備時間）」単元にして範囲を明示した復習コマにする。
- `SOURCES`: `(ID, 資料名, 発行者, URL, 用途)`。S1＝学習指導要領本文、S2＝解説（build_md.py が [S2] を参照する）、S3＝共通テスト実施要項、S4 以降＝編修趣意書など。

## 内容の書き方（最重要）

- 要点は学習指導要領・解説の記述に基づいて書く。題材の例は解説に例示のあるものを優先し、実際に解説本文を読んで確認する（`find_terms.py` でページを探し、`Read` で読む）。
- 学習指導要領の範囲外（教科書の「発展」、他科目の内容）は載せない。教科書では一般的だが解説に明示の記述が見当たらない語句・内容を含む行は `mark="†"`。
- 歴史・地理・公民・理科などの事実を書くときは、解説や学習指導要領に書かれている範囲で書き、年代・人名・数値などの細部は、解説で確認できたものだけにする。
- 手本と同程度の粒度・文体（簡潔な常体）。

## 追加の決定事項と注意（第1・2陣の結果を受けて）

- 利用者の決定:
  - † の行は削らずに載せる。
  - 教科書会社の配当時数は最新の検定版（令和7年度検定など）を使う。
  - 「△」は表現活動・探究活動そのものの行に付ける現行の使い方でよい。
  - 歴史・倫理などで細部（人名・年代・用語）が不足する場合は、教科書レベルの主な語句を † 付きで補ってよい。ただし教科書会社が公開している資料（文部科学省公開の編修趣意書、各社サイトのシラバス案・年間指導計画・評価規準例・内容解説資料など）で確認できた語句に限り、その資料を SOURCES に加え、要点の末尾に「［語句：S12］」のように出典IDを書く。
- 共通テストの対象外の科目（数学Ⅲ、論理国語など）は `EXAM_DEFAULT = {"共通テスト": "—", "個別試験": ""}`。
- 解説 PDF を pypdf で抽出すると本文が文字化けする場合がある（理科編で発生）。日本語が読めない場合は pdfplumber・pypdfium2・pdfminer などで抽出し直し、別キー（例 `hs_kaisetsu_xxx_pdfium`）で保存する。理科編の共有テキスト `hs_kaisetsu_rika.txt` は読める版に差し替え済み。
- `find_terms.py` は部分一致なので、短い語（例「レンツ」が「ローレンツ」に一致）に注意する。
- 「小項目の作り方」の説明文は `METHOD_NOTE` で差し替えられる（時数配分の根拠が年間指導計画以外の場合に使う）。
- 表の欄の中の半角「|」は build_md.py が自動で全角にする。
- 区分「実習」も使える（説明は自動表示）。build_md.py は「実習」の行の共通テスト列を既定で「—」にするため、範囲内なら行ごとに `exam=` で指定する。

## 完了条件と報告

1. `python tools/build_md.py data.<module> "output/<name>.md"` の検証がすべて OK。要確認が残る場合は、解説本文を読んで確認した根拠を報告に書く。
2. 全行の2割以上を無作為に選び、解説本文と照合して誤りがないことを確認（誤りは修正）。
3. 最終報告（日本語）: 生成ファイルのパス、科目別の合計コマ数（別枠を含む/含まない）、単元一覧（コマ数と各社の配当時数）、検証結果、† の行の一覧、判断した点・前提、利用者の判断が必要な点、使った出典。
